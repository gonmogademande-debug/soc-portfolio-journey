RAPPORT D'INVESTIGATION SOC : IDOR & FILE UPLOAD (RCE)

1. RÉSUMÉ DE L'INCIDENT
Lors de tests de sécurité sur l'application web locale, deux vulnérabilités critiques ont été identifiées : une référence directe non sécurisée à un objet (IDOR) et une faille d'upload de fichier menant à une exécution de code à distance (RCE).

2. DÉTAILS DES VULNÉRABILITÉS

A. IDOR (Insecure Direct Object Reference)
- Fichier affecté : /idor.php
- Paramètre vulnérable : id (GET)
- Problème : Le script ne vérifie pas si l'utilisateur connecté a les droits d'accéder au profil demandé.
- Preuve : La requête "curl http://127.0.0.1:8080/idor.php?id=2" a permis d'afficher le profil de l'administrateur et de récupérer une clé API secrète.
- Remédiation : Implémentation d'un contrôle de session côté serveur pour vérifier que l'ID demandé correspond à l'ID de l'utilisateur connecté.

B. File Upload (Téléversement de fichier malveillant)
- Fichier affecté : /upload.php
- Problème : L'application accepte des fichiers sans vérifier leur extension ou leur type MIME.
- Exploitation : Un fichier PHP malveillant (shell.php) a pu être téléversé dans le dossier /uploads.
- Preuve : En accédant au fichier via l'URL, le serveur a exécuté les commandes système (RCE).
- Remédiation : Mettre en place une liste blanche d'extensions autorisées (ex: .jpg, .png), vérifier le type MIME réel, et désactiver l'exécution de scripts dans le dossier d'upload.

3. CONCLUSION
Ces failles démontrent l'importance de valider les entrées utilisateur et de mettre en place des contrôles d'accès stricts. La documentation de ces tests permet de comprendre l'impact réel sur la sécurité de l'application.
