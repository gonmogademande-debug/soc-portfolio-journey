RAPPORT D'INVESTIGATION SOC : LFI & Command Injection

1. RÉSUMÉ DE L'INCIDENT
L'audit de sécurité a révélé deux vulnérabilités critiques sur le serveur local : une Inclusion de Fichier Local (LFI) et une Injection de Commande. Ces deux failles permettent à un attaquant de lire des fichiers sensibles sur le serveur et d'exécuter des commandes système arbitraires.

2. DÉTAILS DES VULNÉRABILITÉS

A. LFI (Local File Inclusion)
- Fichier affecté : /index.php (ou autre script d'inclusion)
- Paramètre vulnérable : page (méthode GET)
- Problème : Le script inclut des fichiers en fonction de l'entrée utilisateur sans valider le chemin (path traversal).
- Preuve (PoC) : curl "http://127.0.0.1:8080/index.php?page=../../../../etc/passwd"
- Résultat : Le contenu du fichier /etc/passwd a été affiché, exposant la liste des utilisateurs du système.
- Remédiation : Utiliser une liste blanche de fichiers autorisés à être inclus, ou valider strictement le chemin avec realpath().

B. Command Injection
- Fichier affecté : /ping.php
- Paramètre vulnérable : ip (méthode GET)
- Problème : Le script passe l'entrée utilisateur directement à une fonction d'exécution système (comme shell_exec).
- Preuve (PoC) : curl "http://127.0.0.1:8080/ping.php?ip=127.0.0.1;whoami"
- Résultat : La commande système whoami a été exécutée, renvoyant l'utilisateur du serveur web.
- Remédiation : Valider l'adresse IP avec filter_var() et échapper les arguments avec escapeshellarg().

3. CONCLUSION
La combinaison d'une LFI et d'une Injection de commande peut mener à une compromission totale du serveur. La validation stricte de toutes les entrées utilisateur est la seule défense efficace.
